# Codex App Server boundary

The MVP includes a transport-agnostic JSON-RPC client in `internal/codexapp`. Its contract was derived from schemas generated by the locally installed Codex CLI:

```sh
codex app-server generate-json-schema --out <temporary-directory> --experimental
```

Verified request flow:

1. `initialize` with AgentHub client name and version
2. `initialized` notification
3. `thread/list` with a page size, updated-time ordering, and `useStateDbOnly: true`

Decoded thread fields are restricted to `id`, `cwd`, `status.type`, and `updatedAt`. Preview, turns, and prompt content are ignored. Status mapping is:

| App Server | AgentHub |
|---|---|
| `active` | `active` |
| `idle` | `idle` |
| `notLoaded` | `inactive` |
| `systemError` | `unknown` |

This client is a foundation, not the daemon's default adapter. Before enabling it, add a supervised stdio/Unix-socket/WebSocket transport, read deadlines, reconnect/backoff, full cursor iteration, and a clear rule for whether a connected but externally launched App Server session counts as managed or unmanaged.
